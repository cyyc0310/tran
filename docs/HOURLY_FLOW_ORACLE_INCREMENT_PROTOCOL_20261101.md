# 同小时净互联流量上限诊断协议

更新：2026-11-01。此实验是消费侧官方标签上的不可部署信息上限，不进入中国主预算。

## 研究问题

上一轮滞后`t−2`月净受电占比没有改善跨域消费侧预测。本诊断问：若模型知道目标小时实际净互联流量，是否能恢复被月聚合抹去的信号？若即使此上限也不能双向改善，消费侧难点就不只是月报时间分辨率。

## 合同

- US→GB、GB→US；源训练2022、源区校准2023、目标评分2024。
- M为日历＋严格滞后`t−2` CN5月统计。Oracle臂在M上增加目标小时实测净受电/系统需求比。
- US：EIA-930 `-Total interchange / Demand`。GB：NESO十条互联线带符号流量求和，按小时能量汇总后除以TSD。
- M和Oracle严格共享源训练行、源校准行和目标评分小时；目标流量不完整的行从两臂共同剔除。比较粗组成Ridge和HistGradientBoosting。
- 2024响应在此前开发中已查看。所有分值仅用于信息价值上限诊断，不能称为真实预测、冷启动部署表现或盲测。

## 禁止的解释

目标小时实际流量在月前预测原点不可见，Oracle结果不属于M或M+C预算，也不能用于中国预测器。若它有增益，只说明高频净流信息有价值；并不能说明实际预测时可获得的流量预报有同样增益。US Demand与GB TSD范围不同，跨方向差异仍含统计口径和标签产品差异。

来源：[EIA-930字段与符号](https://www.eia.gov/electricity/930-content/about.html)、[NESO 2024需求与互联线字段](https://www.neso.energy/data-portal/historic-demand-data/historic_demand_data_2024)。
