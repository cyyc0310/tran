# V249–V251 供体池口径更正

## 发现

V249 runner 的 `aggregate()` 同时对供体档案和目标档案使用同一组 `target_bas` 过滤条件。`run()` 虽然在供体聚合时剔除了目标BA，但档案其余BA也已先被 `target_bas` 限制。因此 r1 实际使用的是“当轮冻结目标名单中的其他BA”，并非协议写明的“全部其他BA”。目标端燃料若在该小名单中无人提供，会导致整个BA-month被跳过。

该问题影响 V249、V250、V251 的 r1 结果。其区间指标只描述受限供体池下实际评分的子集，不能作为协议所述宽供体方法的结果。尤其 V251 的 FMPP 只有5个月进入分数，正好漏掉目标中存在Diesel Oil的月份；GVL的Wood与SEC的Natural Gas也可能受小名单供体支持影响。r1目录和文档保留，方便审计，不覆盖。

## 修正与影响范围

- 供体档案重新聚合时保留EIA-860映射中的全部BA；对每个目标BA仍按BA标识完全排除该BA供体。
- 目标档案、目标BA队列、数据筛选、供体年/目标年、燃料匹配、中心公式、随机种子、1日本地因子预算、12日整日校准预算、重复次数及评分指标均保持原样。
- r2 输出写入新目录，r1 目标队列不增删，不按结果补换地区。此前已经查看了r1目标标签，因此r2是**实现口径纠正后的复算**，不再称盲测；未来盲测必须在修正后的代码路径冻结后另选未评分目标。
- 后续应让供体与目标队列成为两个独立参数，并在运行元数据里记录供体BA集合及每个目标燃料的供体支持数；在当前不改动共享runner的前提下，复算通过运行时包装器把非目标聚合范围设为完整BA集合完成，调用细节在结果文档记录。

复算时，2024 EIA-860 的 `plant_map()` 得到68个映射BA。运行时包装器对 `aggregate(..., target=False)` 传入这68个BA；对 `target=True` 保留本轮目标BA集合。下游仍由原 `run()` 对 `pool.ba != target_ba` 做目标BA排除。r2输出目录分别为：

- V249开发/压力队列：`results/v249-cems-hourly-interval-all-donors-r2/`
- V250冻结单州队列：`results/v250-cems-hourly-interval-all-donors-r2/`
- V251佛州东部时区队列：`results/v251-cems-hourly-interval-florida-east-all-donors-r2/`

三轮复算均完成；V249/V250/V251结果文档中的主表已改为r2口径。V250与V251合并的10个新BA、120个BA-month另用于共同成簇bootstrap，总结写入[突破搜索记录](BREAKTHROUGH_SEARCH.md)。共享runner源文件没有在本轮修改，因此供体与目标集合仍由运行时包装器区分；后续正式复用应把它们做成独立CLI参数并写进元数据。

## 科学结论状态

在r2重跑前，V249–V251关于热输入/局地因子区间收益的数字仅为r1诊断，不能用于论文结论或决定方法是否达标。供体限制通常会减少异质供体数，但它对区间宽度、中心偏差、覆盖与纳入月份的方向都不保证，因此不得靠方向猜测修正r1结果。
