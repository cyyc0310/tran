# V381：上海月表复核与中国逐小时负荷候选源审查（2026-10-31）

## 本轮问题

用户补充：上海水电、核电为零，其余月度发电类别数据在三份附件中。核对附件是否带来V378之外的新数据，并检查一个声称提供中国省级逐小时负荷形状的公开模型项目，判断它能否补上冷启动研究的独立高频信息缺口。

## 附件复核

三份附件为国家统计局“分省月度数据”导出的火力、风力、太阳能发电表。附件本身没有省份字段；上海归属及水电、核电均为零来自用户明确说明。表内列为2026年9月至2025年9月的报告期；仅2025年9–12月与2026年3–9月有11个非空当期月份，2026年2月只有1–2月累计字段。单位为亿千瓦时；注释限定规上工业法人单位统计范围。

对附件SHA-256与V378原始归档逐个核对：火电`92e02b10dbf5d19f3a680b481e005e5b6ada8a32c97d0bc7f805076cb5b10228`、风电`7a6acef4e1503f7b80b7350adaaaea12a7bfe0fec639467c9532b99bdca11ad9`、太阳能`85941ab60c7a99bdeab88d43ca3c386cc409e5fe3a018640900a4abf3fdd8407`，均完全一致。故这次没有新增月份、字段或独立样本；V378中已将用户确认的水电/核电零值计入五类发电分母，原始月值、累计值、与V320对照和阈值扫描均已完成。无需重复运行或改写原冻结结果。

## CEpower候选源审查

公开仓库[Zheng-Energy/CEpower README](https://github.com/Zheng-Energy/CEpower/blob/main/README.md)称`load_shape.csv`为31省×8760小时，来源是电力公司实测；风光容量因子来自ERA5与物理转换。README没有给出负荷数据的电力公司、采集时间、历史/情景年份、覆盖和缺测规则、处理流程、版本或独立验证误差。README虽提供模型代码Apache-2.0许可说明，但这不能自动说明负荷原始数据可再分发。它把“历史回测（以2010/2015输入预测2020/2024实际）”列为未来路线，不能据此视作已完成的历史外部验证。

结论是**有条件的待核数据候选**：仓库描述值得进一步索要数据字典和样例，但当前公开页面的信息不足以把负荷序列登记为经证实的历史测量，更不足以当成小时发电分母、小时CIF标签或覆盖评估真值。即使随后证实它是实测负荷，它仍是需求侧量；只有建立同时间、同区域的发电—净交换—储能/损耗口径合同后，才能讨论是否为CIF的合法分母信息。当前用户设定的主信息预算仍仅为公开月/年发电统计，因此不能把未知来源的小时负荷加入主模型输入。

这和V64审计的2018/2015–2024公开负荷重建数据属于不同来源：V64的数据已经查明由典型曲线、每日高低负荷和天气等重建；CEpower仅作README级来源审查，不能将两者混称或互相佐证。[V64](CHINA_HOURLY_LOAD_PROXY_AUDIT_V64.md)仍是已核实重建数据的结果。

## 对创新路线的更新

新数据没有到来，故本轮不新增上海预测实验。现有证据仍支持“本地月度组成×阈值/因子支持的识别状态审计”作为中国场景基准组件：上海直出数据已证明本地组成与全国池化值在混合水平上明显不同；但这不能识别小时尾数，V373–V377又显示全口径范围残差会消掉若干粗组成收益。更强的算法主张需要真实可得的小时标签，或至少多省原始公开月表和一个可核验的本地边界锚。CEpower暂不能填补该标签缺口。

下一步应优先扩展**原始官方导出的跨省信息基准**，而不是在V380失败后继续调相似度核带宽：选四川、吉林、福建、青海等与上海组成反差大的省份，保存原表、发布日期、字段、单位、当期/累计语义与哈希；检验同一阈值条件化识别状态在不同发电结构下是否复现。该实验只验证数据驱动基准与可识别性分层，不冒充小时预测性能。并行的算法晋级仍须等待合规高频标签和同预算强基线覆盖/效率门槛。

## 边界
