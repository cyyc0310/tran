# V7：V6新地区失败的事后诊断

2026-10-23，全部使用Sol。本报告在V6六个新地区2026H1成绩已打开之后编写；它是开发诊断，不是新确认。没有重新拟合点模型、风险模型或残差bank，也没有修改任何V6冻结代码、输入、预测或结果。真值替换、相位旋转和源支持比较都不能作为合法预测方法或确认成绩。

最有证据支持的失效链是：**四地区2022点形状库覆盖不足，32邻居平均及固定0.5混合进一步压低形状；目标的日内振幅和组成发生源外漂移，同时日均水平仍被高估；2024七源残差bank及条件尺度无法充分补偿。** 能量加权月CIF与均匀小时均值确有额外差异，PSCO还存在长粗统计空档，但两者不能单独解释全部失败。原始native质量没有发现足以解释主要误差的净发电记账失败。

## 实际点训练域只有四个

同时核对原始点run的`run_config.json`、被V6复制的点模型字节和反序列化对象`model.structural.source_regions`，结果完全一致：

|用途|年份/分割|地区|
|---|---|---|
|原始点模型、template及analog shape库|2022|BPAT、ERCO、MISO、NYIS，仅四区|
|V6条件残差模型proper fit|2024H1|原七区，1,266个有效地区日|
|V6配对残差bank|2024H2|原七区，1,000个有效地区日|
|V6方法/倍率选择|2025|原七区|
|已失败的外部确认|2026H1|AZPS、DUK、LGEE、PACE、PSCO、SRP|

所以“原七区都参加了V6”不等于“2022点形状模型训练过全部七区”。CISO/FPL/ISNE不在点训练域。CISO太阳能能量份额在2024/2025达到22.5%/25.8%，但只进入后续残差学习/开发；实际点训练库中ERCO 2022太阳能占5.52%，是四区最高值。该库1,211条完整日路径的shape RMS中位数13.49、95%分位44.23、99%分位66.61、最大100.56；共享月template的RMS仅5.26–8.57。

不能进一步声称“源完全没有太阳能或西部形状”：四区中ERCO确有太阳能，七区残差bank还包括CISO。准确结论是**实际点形状训练支持较窄，后续残差源虽更广，仍未覆盖目标常见的振幅和形状分布**。

## 目标振幅显著超出源，原始点尤其平

下列构成是保留小时上的发电能量份额。目标只统计2026H1；源2024/2025全年结果另列在CSV，不能混称同季节匹配。

|目标|太阳能|风能|真值日内shape RMS|原始点shape RMS|ensemble均值shape RMS|真值/RMS超过2022库最大值的日比例|
|---|---:|---:|---:|---:|---:|---:|
|PACE|15.43%|31.16%|140.42|12.99|25.41|64.44%|
|AZPS|25.85%|13.74%|114.26|12.84|25.85|60.34%|
|PSCO|10.94%|44.11%|72.07|12.22|21.94|12.22%|

预测列为源固定主`harmonic_ridge/structured_x1p25`、额外延迟0；真值与预测用完全相同的完整UTC日。七源2024/2025全年最大的整体shape RMS为ERCO 2025的57.41，仍低于上述三目标。源与目标有效日期不同，不能把年度差异全部解释为单一燃料的因果效应。

实际32邻居几乎都来自ERCO：PACE权重98.22%、AZPS 99.97%、PSCO 93.51%。邻居单路径加权平均RMS分别约35.94、36.37、32.57；把这些路径取均值后仅19.30、19.09、17.33，再与弱template按0.5混合，得到约13的点形状。邻居方向不一致的平均抵消与固定收缩叠加，不能由增加水平区间宽度修复。

近邻粗特征距离也不是充分的安全检查。PACE的最近标准化距离均值只有0.82，PSCO为8.11；PACE在粗特征空间看似接近某些ERCO日，却仍严重缺少对应小时形状。月度组成不唯一确定日内出力和总发电的联合分布。

## 相位要区分原始点与完整ensemble

所有相位均为**UTC小时起点**，不等于当地民用时间，更不是已经核实的太阳时。

|目标|真值平均profile最低时刻UTC|原始点最低UTC|ensemble均值最低UTC|原始点/真值profile余弦|ensemble均值/真值余弦|
|---|---:|---:|---:|---:|---:|
|PACE|19|8|16|0.022|0.720|
|AZPS|20|8|17|0.027|0.673|
|PSCO|19|7|16|0.101|0.803|

原始点最低时刻错开约11–12小时，但**不能把整个预测等同于一条纯粹平移11小时的曲线**。事后寻找最优循环平移后，原始点profile余弦也仅约0.56–0.58，幅度和形状仍不匹配。完整ensemble的源残差已部分改正方向和相位，真正留下的主要问题是日内幅度仍明显偏小，且水平偏差没有消失。

AZPS和PACE的逐小时CIF与太阳能小时份额相关分别约−0.799/−0.700，符合太阳能增加时固定EF代理下降的方向；这只是同小时描述关系，不能识别独立因果效应。PSCO风能份额44.11%，不能把其失败一概归于太阳能或单一时钟问题。

## 日均水平与形状都错，残差bank不是万能补偿

下表仍为额外延迟0；signed bias定义为**truth−prediction**，负值表示高估。单位为固定EF代理gCO2/kWh。

|目标|原始日均bias|原始level MAE|原始shape MAE|ensemble均值日均bias|ensemble均值level MAE|ensemble均值shape MAE|
|---|---:|---:|---:|---:|---:|---:|
|PACE|−92.65|110.94|117.14|−71.31|104.30|104.31|
|AZPS|−112.17|112.53|101.92|−90.53|94.30|88.01|
|PSCO|−82.87|103.37|55.53|−39.51|84.87|51.07|

将`truth−corrected_point`按档案中的component scale与1.25倍率标准化后，PACE/AZPS/PSCO有47.78%/26.82%/8.33%的目标日，shape RMS超过整个2024H2源bank的最大值；目标逐小时标准化shape误差落在各小时源bank全范围之外的比例为31.37%/18.09%/6.90%。这些是支持不足的直接描述，不能变成概率覆盖保证。

bank并不是每个源都有半年：BPAT180、CISO181、ERCO69、FPL180、ISNE26、MISO182、NYIS182日。实际采样先地区等权，再地区内均匀；少量源日被反复使用。`source_bank_support.csv`中的全bank p95、p01–p99为**未加权行描述分位**，不是实际地区等权预测分位；最大范围检查不受这一权重区别影响。逐源统计在`bank_by_source_region.csv`。

粗特征也已外推。额外延迟0时，AZPS/PACE/PSCO年度差RMS均值为91.30/60.96/67.89，全部目标日超过proper-fit的最大45.01。三地季节与harmonic有符号hindcast bias也大多超源proper范围。历史月计数超范围有时间增长的机械原因，不应单独作为失败证据；主structured也没有使用全部17个特征，不能把任何一个未使用特征越界都解释为该模型的因果机制。

## 月CIF的聚合口径与统计滞后

对同一批保留小时，分别计算`mean(CIF_hour)`和`sum(generation×CIF)/sum(generation)`，不把mask差异混进聚合偏差。六目标2026每个已导出粗月与同月retrospective能量加权值一致到浮点误差，观测小时数也相同。

|目标|六个月平均：能量加权−均匀小时CIF|单月最大绝对差|
|---|---:|---:|
|PACE|−13.01|21.14|
|AZPS|−21.16|31.26|
|PSCO|−7.30|10.73|

数学上该差等于`Cov(total_generation, CIF)/mean(total_generation)`。它在太阳能较多的新域明显大于许多旧源，但只有约7–21的月平均量级，小于主要的83–112原始日均高估；且能量加权值更低，**不支持把已经发生的高估完全归咎于“直接把月CIF当小时均值”**。这仍是需要单独处理的聚合口径，不是现成的全部修复。

`residual_and_asof_by_month_delay.csv`按地区、月、额外延迟记录真值日均、原始点日均、最新合法粗月、年龄及误差。

- PACE额外延迟0时，6月最新合法粗统计均值374.23，真值日均434.81，但harmonic原始点仍为534.94。已有较低粗月没有充分打破历史周期外推；“再等一份统计”不是唯一解释。
- AZPS额外延迟0时，4月真值305.64、最新合法粗值430.85、点474.75；6月真值406.81、最新粗值292.78、点518.11。信息陈旧与周期外推的方向随月变化。
- PSCO 2025H2没有合格粗月，2026年初最新合法月仍是2025年6月。即使额外延迟0，1/2月平均观测年龄已达199/228.56天；额外延迟90时，5月平均319天。这不是名义“月末+30日”所能概括的实际信息年龄。

完整CSV保留所有地区和延迟，不能只挑表现最差的月份作为代表。2024/2025历史目标有效日覆盖并不一致，报告不把不匹配日历与质量mask的年度均值直接解释为技术趋势。

## 非法oracle只用于分辨瓶颈

对已冻结完整128情景ensemble做以下替换，不重新采样、拟合或选择：

1. `level`：每个情景日均替换为真值日均，原情景零均值shape完全保留。
2. `shape`：每个情景shape替换为真值shape，原情景日均完全保留。
3. `both`：直接替换为真值，分数接近零，仅是恒等检查。

不重新clip，避免破坏精确组件恒等式；越固定EF支持的比例另报。每种替换都非法使用目标真值并删去对应不确定性，不是可部署方法，也不是合法条件下能达到的改进承诺。oracle收益非线性、不可简单相加，覆盖/宽度也未必同时变好。

下表对三延迟等权，沿用原完整ensemble的CRPS与经验inverse-CDF分位口径。

|目标|原ensemble CRPS|真值level oracle|真值shape oracle|
|---|---:|---:|---:|
|PACE|127.3150|88.9740|84.4404|
|AZPS|98.7096|70.7645|75.6576|
|PSCO|75.5732|38.8173|64.7054|
|六区等权|64.7348|40.1996|50.0077|

PACE同时受大形状和水平误差限制；PSCO的CRPS更偏向水平瓶颈，AZPS两者都重要。完美替换level后，AZPS覆盖反而从75.44%降至45.67%：原level不确定性在一定程度上掩盖了shape不足，不能把全部宽度迁到某个组件就宣布校准成功。

## QA与复现

新诊断native QA按准备audit的2026 `source_snapshots`拼接原始文件，包含2025 Jul–Dec提供的年初UTC小时，不能按文件名只选2026 Jan–Jun。跨快照`(region,valid_at)`必须唯一；每区retained native时间戳集合与导出`valid=True`小时完全相等。

PACE/AZPS/PSCO分别重现4,320/4,296/4,320个保留native小时，保留小时的原有signed native记账失败数均为零；负发电正部截断占代理正能量约0.0027%/0.0506%/0.0696%。PSCO被排除storage/unknown净能量约占代理正能量4.683%，是代理定义边界，不能当完整电网排放事实。SRP截断比例更高（约0.927%）但预测覆盖较好，不支持把截断大小当作这次主要失败的统一解释。

运行命令：

```bash
"../tran-stable/.venv/bin/python" scripts/diagnose_failure_v7.py \
  --output results/failure-diagnosis-v7
```

输出必须使用新目录。最终目录`results/failure-diagnosis-v7/`包含12份CSV、两组PNG/PDF、训练与bank来源JSON及诊断metadata。metadata对136份输入/代码文件留存SHA256，执行前后核对；原V6 package闭包逐项重核一致，所有源2025和目标2026地区×延迟的原始ensemble CRPS/覆盖/宽度/区间评分逐项重现原V6 regional表。11项测试覆盖CRPS配对恒等式、实际V6分位约定、无clip oracle组件恒等、UTC相位、同小时能量加权差、as-of与extra lag、bank支持、native跨年边界/重复/缺失及拒绝覆盖输出。

两个中间目录保留而不作为最终报告：`failure-diagnosis-v7-attempt01-linear-quantiles`使用初版线性分位（CRPS未受影响）；`failure-diagnosis-v7-attempt02-native-boundary`已修分位，但其native QA只按文件年份取输入而漏掉年初边界小时。最终版本修正这两处，未改任何V6数字。

这次诊断支持优先检查形状训练支持、小时组成映射、水平趋势与真实信息年龄，并明确粗统计对未来小时路径的不可识别部分。它不证明某个新结构已经有效，更不恢复这批已看目标作为未见确认的资格。
