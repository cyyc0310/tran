# 月度逐燃料库存能否补救六小时热组汇总？

2026-10-27，Sol。为审查粗分辨率阶梯对月度燃料细分的忽略，在2024 H1的七个已查看代理区每个来源月取UTC月中完整日，建立联合线性规划。共42个来源月、1,008个小时。输入约束为：逐燃料月总发电量、每小时总发电量、每6小时正EF组总发电量。对每个取样小时分别最小化/最大化固定EF排放分子，得到信息合同下的精确sharp边界；真值均在内。

该配置是回顾性 oracle：逐燃料月总量及六小时正组总量都使用目标月份最终观测，不代表预测时可得。它也没有机组爬坡、容量、启停、EF不确定性或潮流约束。与之对照的`coarse_only_width`使用相同小时总量、六小时正组总量，但不约束逐燃料月库存。

这个结果改变了前一轮的一个潜在解释：月度类别库存确实会与块级热组约束产生额外收紧，但效果高度依赖来源；对ERCO和MISO，即使授予已知目标月各燃料总量，6小时热组轨迹仍未缩小逐小时集合。对所有来源而言，联合边界宽682仍约为实际小时CIF标准差的5.7倍。因此，不能把“加月度类别列”视为替代小时调度形状信息的充分条件。

这不是新优化算法：线性规划只是把已知边际和块总量写成可行集合。可保留的研究价值是一个有方向性的可识别性结论：相同的粗统计合同不能跨地区提供统一小时精度，平均覆盖/平均误差会掩盖ERCO/MISO式零收紧。下一步应比较相同物理约束下6小时与1小时组量，及其是否能对未参与开发地区给出有用的保守预测集合；目前结果仍然是事后代理区的oracle界。
