# V390：三日主动补报的乐观上限

## 研究问题

V201/V202比较随机、月初、均匀日期补报，但没有判断“选日策略”本身的最大潜在价值。本轮先求一个**oracle上限**：如果事后知道每一天的真实分时燃料结构，最多能把月阈值小时数的部分识别区间缩窄多少？只有当上限明显高于随机/均匀策略时，才值得开发不看目标小时标签的源区选日模型。

## 固定数据、对象与预算

- 沿用V202的25个EIA平衡区、2024-07至2025-12完整UTC日、固定燃料EF、相同质量筛选与V202 `block_bounds` / `bounds_for_selection`；不引入新地区、新燃料因子或容量假设。
- 主要预算为目标月额外报告3个UTC日、每日报告4个连续6小时块的8类燃料电量，共`3×4×8=96`个数值字段。
- 主要阈值为300 gCO₂/kWh；100 gCO₂/kWh作为压力诊断。风险目标频率沿用1%、5%、10%。
- 对每个地区月穷举全部三日组合，选择使`τ=300`月K识别区间宽度最窄的组合。这个选择使用实际目标月日内燃料边际，是不可部署的oracle；它只给主动选日方法提供上限，不作为预测或效果主张。
- 基线使用V202相同预算的均匀间隔、月初和随机三日方案。报告原始小时宽度及相对月度基线的归一化宽度；所有方案均须包含同一同期观测K。

## 继续/停止门槛

- 若oracle最佳三日相较V202最佳非oracle三日的区间宽度改善很小，停止“仅优化选日”的方法线。
- 若oracle上限大而已知日程策略差，才值得另开严格源区训练、目标区/未来时间隔离的可部署选日预测器；不能把oracle结果包装成算法增益。

## 限制

这是一项EIA估算燃料小时序列上的信息价值上限诊断，不是中国实测CIF，不是统计覆盖率，也不表示用户可合法获得目标日分时数据。它不能替代V202，也不重新证明部分识别边界。
