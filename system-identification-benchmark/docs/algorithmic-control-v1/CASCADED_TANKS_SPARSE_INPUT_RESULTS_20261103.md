# Cascaded Tanks 稀疏输入预测扩展：结果与边界

日期：2026-11-03。状态：公开数据开发期结果，**不是盲测、官方原始测试分数或独立确认**。源数据准入和协议分别见[数据审计](CASCADED_TANKS_SOURCE_ADMISSION_AUDIT_20261103.md)与[冻结任务协议](CASCADED_TANKS_SPARSE_INPUT_PROTOCOL_V1_20261103.md)。

## 任务是什么

数据来自实体级联双水箱，记录间隔为 4 秒，输入是泵信号，输出是下水箱传感器读数。官方文件提供一条 1,024 点估计记录和一条 1,024 点测试记录。官方协议不允许用测试记录估计模型；本扩展另行定义了一个公开测试前缀校准任务，所以其数字不能称为官方未触碰测试成绩。

比较固定估计记录训练的 ARX 和二次多项式 SINDYc 风格模型、零阶保持，以及每种模型使用 1、3、5 个目标转移（4、12、20 秒）拟合的单一输出路径倍率。每个预测块给定该块实际记录的泵输入，并用块起点实测输出重置模型；预测跨度为 4、12、20 秒。因此它测的是**离线、给定记录输入的分块条件预测**，不是未知未来输入预测、全程不重置滚动或闭环控制。线性端点插值使用真实块终点，仅作离线 oracle，不参加因果方法排名。

测试记录的标签曾在数据准入时查看，且同一记录的预测块不是独立重复。以下结果只能用于开发阶段观察和提出下一步假设。

## 主要结果

以估计记录输出标准差归一化的 RMSE（NRMSE）如下。数字汇总自 20 秒预测跨度；每格含一个测试轨迹内的 203–204 个不重叠块，它们仍属于同一条记录，不是 203–204 次独立试验。

| 方法 | 目标前缀预算 | NRMSE | 对照解释 |
|---|---:|---:|---|
| ARX，冻结 | 0 秒 | 0.0959 | 未用目标前缀 |
| SINDYc 风格模型，冻结 | 0 秒 | **0.0924** | 该任务中两种冻结模型的较低值 |
| 零阶保持 | 0 秒 | 0.1414 | 简单基线 |
| ARX，路径倍率校准 | 4 / 12 / 20 秒 | 0.1482 / 0.1455 / 0.1424 | 均高于冻结 ARX |
| SINDYc 风格模型，路径倍率校准 | 4 / 12 / 20 秒 | 0.1479 / 0.1468 / 0.1429 | 均高于冻结模型 |
| 端点线性插值 oracle | 不适用 | 0.0206 | 读取真实预测终点，只是离线参照 |

在 4、12、20 秒三个跨度下，冻结 ARX 和冻结稀疏模型均优于零阶保持。目标路径倍率校准则在两个模型的全部 9 个“预算 × 跨度”条件中都比相应冻结模型误差更大；20 秒跨度恶化约 33%–55%。

前缀训练误差下降并没有转成后续收益：4 秒预算下拟合出的倍率约为 0.005–0.009，使单个短前缀误差几乎归零；12 秒和 20 秒预算下倍率为负。对 SINDYc 风格模型，倍率分别约为 0.0090、−0.0426、−0.0158。该现象说明这套极低自由度倍率校正不能从这些短前缀中可靠推断后续路径修正方向；它不说明所有目标校准或所有设备都无效。

## 模型与激励诊断

- ARX 为 `y[k+1] = c + a*y[k] + b*u[k]`，在完整估计记录上满秩；二次稀疏模型使用 `[1, y, u, y², y·u, u²]` 拟合离散导数。阈值 0.3 在估计记录的按时间留出段选中，随后冻结支持集 `[1, y, u, y², u²]`，只在完整估计记录重估这些项的系数。
- 目标 4 秒前缀仅 1 个转移，ARX 回归秩为 1/3，稀疏库秩为 1/6；12 秒前缀的 ARX 虽达 3/3 秩，列归一化条件数仍约 34,290；20 秒前缀 ARX 条件数约 2,396，二次库只有 5/6 秩。满秩并不等于参数估计稳定。
- 官方基准说明将输入定义为泵电压、输出定义为下水箱的水位传感器读数；传感器未校准，观测还含测量误差，且存在上水箱溢流和输入相关过程扰动。[官方说明 PDF](https://cris.vub.be/ws/portalfiles/portal/24190624/CascadedTanks_Maarten.pdf) 物理水位状态本身应非负，但不能把带误差、未校准的传感器读数直接裁剪为非负状态。文档没有给出实际高度单位、传感器校准曲线、罐体高度上限或泵额定电压范围；因此 `y=10` 仅是观测信号的饱和诊断，数据输入范围也不当作设备安全界。

## 下一步含义

这项外部系统结果与 InTaSet 的稀疏前缀 Adam/L-BFGS 结果方向相同：前缀拟合改善或参数调整本身不足以保证多步预测改善。它仍只是一条公开测试轨迹上的开发证据，不能用来估计适配失败的普遍概率，也不能确认某种风险门控。

因此先停止增加优化器和倍率校准变体。更合适的下一目标是：**在完整运行作为评测单位的嵌套开发中，比较冻结源模型、目标端简单模型和最多一种原论文可复核的低自由度适配器；检验哪些预算内前缀诊断能预示适配会改善还是恶化指定输入下的多步误差。** 所有已查看测试记录只作开发数据；升级为算法主张前还需冻结方法，并用新整条运行或新设备独立确认。
